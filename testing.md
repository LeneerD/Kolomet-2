Инструкция по запуску тестов для бота Trench Crusade
Эта инструкция поможет вам быстро и правильно запускать тесты после внесения изменений в код бота. Тесты проверяют корректность парсинга бросков, работу с таблицами, базой данных и проверку донатеров.

📌 Перед запуском: подготовка окружения
1. Убедитесь, что у вас установлен Python 3.8 или новее
Проверьте в командной строке (терминале):

bash
python --version
Если Python не установлен, скачайте его с python.org.

2. Перейдите в папку с проектом
Откройте командную строку (терминал) и перейдите в корневую папку бота (где лежат bot.py, config.py, папка tests/ и т.д.):

bash
cd C:\путь\к\вашему\боту
Совет для Windows: Откройте папку в Проводнике, кликните в адресную строку, введите cmd и нажмите Enter – вы сразу окажетесь в нужной папке.

3. Установите зависимости для тестирования
Выполните команду:

bash
pip install pytest pytest-mock
Если pip не работает, попробуйте:

bash
py -m pip install pytest pytest-mock
🔧 Настройка переменных окружения для тестов
Тесты импортируют модули бота, которые требуют переменных окружения VK_TOKEN и GROUP_ID. Чтобы тесты не падали, задайте фиктивные значения.

Для Windows (PowerShell или cmd):
В PowerShell (рекомендуется):

powershell
$env:VK_TOKEN = "test"
$env:GROUP_ID = "1"
В классической командной строке (cmd):

cmd
set VK_TOKEN=test
set GROUP_ID=1
Для macOS / Linux:
bash
export VK_TOKEN=test
export GROUP_ID=1
Можно также задать переменные через файл .env, но проще указать их прямо в сессии терминала.

🚀 Запуск тестов
После подготовки окружения выполните:

bash
python -m pytest
Если тесты проходят успешно, вы увидите зелёные галочки и сообщение вида:

text
============================= test session starts =============================
collected 30 items

tests/test_parsers.py .......... [ 33%]
tests/test_utils.py .......     [ 56%]
tests/test_tables.py ........   [ 83%]

============================= 30 passed in 0.25s ==============================
🎯 Запуск конкретных тестов
Один файл:

bash
python -m pytest tests/test_parsers.py
Один тестовый класс:

bash
python -m pytest tests/test_parsers.py::TestParsers
Один конкретный тест:

bash
python -m pytest tests/test_parsers.py::TestParsers::test_parse_single_component_simple
Показать подробный вывод (verbose):

bash
python -m pytest -v
📊 Проверка покрытия кода (опционально)
Если вы хотите увидеть, какие строки кода покрыты тестами, установите pytest-cov:

bash
pip install pytest-cov
Затем запустите:

bash
python -m pytest --cov=. --cov-report=html
После выполнения откройте файл htmlcov/index.html в браузере – там будет интерактивный отчёт по покрытию.

⚠️ Частые ошибки и их решение
Ошибка	Причина	Решение
ModuleNotFoundError: No module named 'vk_api'	Не установлена библиотека vk-api	pip install vk-api
Exception: VK_TOKEN и GROUP_ID должны быть заданы...	Не заданы переменные окружения	Задайте VK_TOKEN и GROUP_ID (см. выше)
sqlite3.OperationalError: no such table: aliases	База данных не инициализирована	Убедитесь, что тесты используют init_db() перед запросами (уже сделано в фикстурах)
AssertionError	Логика бота изменилась, и тест устарел	Обновите тесты под новый код или исправьте ошибку в коде
pytest не распознаётся	pytest не добавлен в PATH	Используйте python -m pytest вместо pytest
💡 Рекомендации
Запускайте тесты после каждого изменения – это поможет сразу заметить ошибки.

Не коммитьте код, пока все тесты не проходят – если тесты красные, значит что-то сломано.

Добавляйте новые тесты для новых функций – это обеспечит их стабильность в будущем.
